# AGENTS.md

Working brief for AI coding agent, not docs for people (README covers that): invariants, gotchas and decisions needed to change *this project* correctly without rediscovering them.

## Hard rules

- `demo/` holds screenshot and GIF rig: `stage.sh` builds fake `~/.ssh` in `demo/home` (fake hosts, generated keys, seeded history, placeholder tunnels) with HOME and every XDG variable redirected into it; VHS tapes render `readme-assets/` from it. Tunnel, mount and login cannot be faked, so `raspi` is throwaway sshd on 127.0.0.6 (invented user, hostname, home): built into render image and started as root before each tape under `render.sh`, `stage.sh` handing it key through `/run/raspi`; on bare machine, in podman container of its own. Staged `ssh` wrapper points every ssh at staged config and known_hosts, for reason in staged `HOME` rule below. `stage.sh down` unmounts anything under stage before deleting and refuses if that fails, because recursive delete walks through mountpoint onto remote side and deletes its files. `up`, `shell` and `run` also refuse while any sshfs mount outside stage is up, because essh lists every mount in `/proc/mounts` and tape's Enter could unmount real one.
- `demo/render.sh` renders every tape (or named ones) in container, so machine needs only podman or docker: image is `demo/Dockerfile`, each tape gets own container that stages, records, tears down. Container starts as root only to start raspi's sshd, then runs tape as you through `setpriv`; needs `--device /dev/fuse --cap-add SYS_ADMIN` for sshfs mount, never `--privileged`.
- **Staged `HOME` does not move ssh's own config**: OpenSSH takes `~` (user config, known_hosts) from passwd home, never `$HOME`, while essh honours `HOME`. Without staged wrapper every ssh essh spawns reads renderer's real `~/.ssh`, whose `RemoteCommand` or `ProxyJump` can break staged login, tunnel or mount while frame shows host with neither. Production essh must not pass `-F`, so rig handles it, never tool.
- Tests never touch real `~/.ssh`: `App::empty()` and `sshcfg` `*_in(path, ...)` helpers keep everything on temp files. TUI tests (`tui/tests.rs`) use ratatui's `TestBackend`, never `script` or pty (alt-screen not captured); how it looks is checked by rendering tape and looking at frame.

## Invariants and gotchas
- Adding host with IdentityFile: if exactly one shared block (`Host a b c` line with 2+ concrete aliases) already sets same key, append new alias to that block and give new host block without own IdentityFile; else write self-contained block. Never join one-alias block (normal per-host block, not group); never touch block when zero or several match, so tool only extends group user already made shared.
- Host sets `RemoteCommand`: write `RequestTTY yes` beside it (`render_block_lines` does), else forced command gets no terminal and shell has no prompt, no line editing. ssh refuses command line on top of one (`Cannot execute command-line and remote command.`), so `essh <alias> <cmd>` fails on such host by design; `ssh -N` unaffected so tunnels work, `scp` passes `-oRemoteCommand=none` itself, our sshfs argv gets same immunity via `-o ssh_command=ssh -o RemoteCommand=none`, only route that works: libfuse checks sshfs options strictly and answers ssh option with `fuse: unknown option(s)` instead of forwarding, so `-o RemoteCommand=none` straight to sshfs fails every mount. Wrapper added **only for host that really forces command** (`sshcfg::forces_command`, asked once when wizard opens, carried in `Action::Mount`): elsewhere it is no-op doubling length of command preview exists to teach. Host list alone cannot answer, because `merge_hosts` drops pattern blocks and `Host *` can force one; pattern too rich for `glob_match` answers yes, since needless `RemoteCommand=none` costs longer line, missing one costs mount failing with nothing readable. Never append `RemoteCommand` to shared `Host a b c` block: unlike IdentityFile it is per-host, would force command on every alias in group.
- Adding host from paste: `[user@]host[:port]` typed into add wizard's Alias field is split across fields on leaving it (`sshcfg::parse_target`); only in add wizard, since doing it while editing would rename existing host behind user's back, and only for string that really is destination, since plain word is someone typing alias.
- Listing hosts: one alias may span several `Host` blocks (per-host block for HostName/User plus shared `Host a b c` block adding common IdentityFile); `merge_hosts` collapses them into one entry with ssh's first-value-wins per field, so never emit one entry per block. First-wins holds inside block too (`set_once`); `Match` line ends Host block above it, since what follows applies only when its condition holds.
- Editing or deleting host: works only when alias is sole name on its `Host` line; shared `Host a b` block refused, because one alias cannot be rewritten in isolation. Every config write backs up first to `config.bak.<epoch>` and rewrites only touched block, in place (`set_key`), never reformatting file; blank `IdentityFile` field removes only first one, because ssh tries every one and form shows only first: comments, keys form has no field for and user-set `RequestTTY` stay where they were.
- Tunnels: every forward opened is kept as line in `~/.config/easyssh/tunnels` (`-L 8080:localhost:80 raspi`, plus ` = a label` when typed); `~/.local/state/easyssh/tunnels.tsv` holds what runs now. Forward identified by what it does (flag, spec, host): that triple is line's key and `entries()` joins two files on it; name is optional label on top, never identity, so renaming cannot collide and nothing needs name to be listed. `Entry::label()` spells unnamed row from its ports (`raspi:80 → 8080`, `3000 → raspi:9000`, `SOCKS on 1080 → raspi`), so list reads without annotating file. `-D` (SOCKS) spec is `port` or `bind:port` with no target, so `ports()` is `None` for it and every `-D` branch (label, `explain`, wizard's single `Local port` field, `e`) checked before `-L`/`-R` port code. Anything running with no line of its own adopted into file by `entries()`, so "running" and "kept" never disagree and row can always be turned back on. Line written before tunnel starts, because forward that will not come up is exactly one you want left in list to fix. Tunnels assume key or agent auth, since detached `ssh -N` cannot answer password prompt. After spawn, code waits about a second, then checks pid and ssh's stderr (`forwarding_failed`), so dead-on-arrival tunnel returns ssh's words instead of leaving phantom entry: taken port leaves ssh running with no forward, so pid alone reads as up.
- Tunnel or mount liveness and kill: reads `/proc`, shells out to `kill` and `fusermount`, so Linux-only; macOS or BSD need different check first. Tunnel alive only while `/proc/<pid>/cmdline` still holds *this* forward's flag, spec and host, never merely because `/proc/<pid>` exists: state-file pid can outlive reboot, and recycled one would otherwise read as up and be what Enter or `d` kills.
- Copying (`essh cp`): rsync only where it lands everything where scp would, so choice never changes result: rsync on both machines (asked with `rsync --list-only` in BatchMode, so password host gets scp and one prompt), one remote host with every source on same side, destination already a folder (into new name rsync nests folder one level deeper than scp), no bare `~` (rsync reads it as file named `~`). Source's trailing slash dropped, since scp copies `dir/` as folder and rsync would copy its contents. rsync's ssh gets options scp passes its own (`SSH_OPTS`, from `scp.c`); rsync runs `-rL` so symlink arrives as what it points to and no owner or time kept, as with scp; progress flags only to terminal. Every source on one side, destination on other, because rsync refuses copy within one host and mix of local and remote sources. Any failure exits 1, never rsync's own code. scp gets `-r` for any remote source, because `scp -r` copies lone file as plain `scp` does.
- Listing keys: `keys::agent` asks `ssh-add -l` once, returns `Agent`: exit 2 is `NotRunning`, exit 1 with empty stderr is empty agent, exit 1 with stderr (failed fetch) or `ssh-add` that cannot run is `Unreadable` with ssh-add's words; so `Key::agent_loaded` is `None` whenever agent could not be asked, and `essh key ls` says which on first line. Agent key with no pair in `~/.ssh` is row too: when its comment is absolute path of pair with its fingerprint (what `ssh-add` writes for key with no comment) it is that pair, named by `~`-collapsed path; else `path: None`, named by comment. Key and its certificate share fingerprint, so `y` on `path: None` row takes `ssh-add -L` line matching both fingerprint and type (paired through `ssh-keygen -lf -`); `Y` and `key install` refuse such row, since ssh-copy-id needs file.
- Generating RSA key: pass `-b 4096`, because `ssh-keygen -t rsa` defaults to 3072 and RSA only chosen for legacy hosts kept for years. ed25519 has one fixed size, takes no `-b`.
- Labelling anything user-facing: `meaning (real command)`, e.g. `mount a remote folder locally (sshfs)`, `fix "host key changed" (ssh-keygen -R)`. Command-only unreadable to beginner; verb-only teaches nothing, leaves them stuck without tool.
- Fields with `Ctrl-o` picker: add/edit-host IdentityFile (keys in `~/.ssh`) and ProxyJump, tunnel wizard's Host (listed aliases), all through `PickerAction::FillField`. `wizard.rs` finds them by field label (`IdentityFile`, `ProxyJump`, `Host`), so renaming label silently drops its picker.
- Mounting: refuse with install hint if `sshfs` not on PATH. Default mountpoint `<mount_root>/<host>` (`~/sshfs/<host>` out of box), so leftovers stay grouped; absolute, since relative default puts mounts wherever essh was launched from. Expand typed `~` with `sshcfg::expand_tilde` (children spawn without shell, so `~/dir` would become directory literally named `~`). `remove_dir` mountpoint after successful unmount; `remove_dir` removes only empty directory, so mount placed over dir with real content never deleted. Every mount kept like tunnel: `local <- host:path` line in `~/.config/easyssh/mounts` (plus ` (sudo <server>)`), keyed by local folder as `/proc/mounts` spells it (`fs::canonicalize` after folder made, since trailing slash or symlinked root would never match), written before mount tried. Enter and `d` as Tunnels; `e` reopens wizard over line (`Prompt::edit_mount`, login carried, not asked): unmounts first, keeps wizard open when that fails, mounts new answer, drops old line only once new one is in file under another mountpoint. Mountpoint another kept or live mount already uses refused with wizard left open (`App::mount_at`), in `c`/`m` as in `e`, since writing it would replace that mount's line; sshfs checked before old mount comes off; live mounts with no line adopted by `mounts::entries()`. Sudo server lives only in that line, because `/proc/mounts` does not show it. sftp has no `~`, so typed leading `~/` dropped from remote path (`mount_spec::remote_path`) and `Mount::describe` puts it back for display.
- Adding TUI action: `c` creates in every view but Mounts, where mount starts from its host with `m` on Hosts (`n` deliberately unbound); on Tunnels `c` opens wizard with host as field, since that tab has no host to read. `y` copies to clipboard (public key text on Keys); `Y` is loud version writing on another machine (ssh-copy-id, picker showing login each alias resolves to, since `admin@box` and `pi@box` are different authorized_keys files), so pair never guessed backwards. `d` gate covers host, kept tunnel and kept mount alike, stopping tunnel first if up; Enter stops tunnel or unmounts at once, since trivially redone. Hosts has no `y`: copying `ssh <alias>` is what Enter already does better from inside tool. Each tab's footer is its `*_KEYS` list in `tui/mod.rs`.
- Filtering: every `selected_*` goes through `*_rows()`, since selection indexes *filtered* rows. `filter::matches` filters, never re-ranks, since Hosts order already earned by `history`.
- Deciding which host is machine essh runs on (`machine::ThisMachine`, read once per `refresh_hosts` into `App::here`, once per CLI listing): host is this machine when alias or HostName is kernel hostname's first label (any domain, case-insensitive, never `localhost`) or one of this machine's non-loopback addresses, and it has no ProxyJump and no Port other than 22. No DNS lookup, because listing hosts must not wait on network. Loopback, other port and jump left out because each is usually forward, container or name resolved on another machine (demo stage's hosts all sit on 127.0.0.x with Port), and hiding real destination costs more than listing yourself. Nothing user sees offers this machine, but code keeps it: stays in `hosts`, because `is_dest` needs its entry to tell which tunnels and mounts go through it and `first_hop` needs it for host jumping through it; each place hides it where drawn. Hosts: `App::listed` inside `host_rows`, title count and empty message counting only listed hosts; every host picker (tunnel wizard's Host, ProxyJump, `Y`, host key goes through) offers `App::listed_hosts`; key's Used by names only `App::used_by`; Tab completion (`completion::hosts`) leaves it out too. `~/.config/easyssh` shared between machines too, so kept tunnel or mount through this machine left out same way while off (`ThisMachine::hides`, reading its `[user@]host` through `is_dest`, inside `tunnel_rows` and `mount_rows`, titles and empty messages counting only listed rows); running one stays, since it is process here and its row is how you stop it. `mount_at` still checks every kept mount, because hidden one still holds its folder. `essh ls`, `essh tunnel ls`, `essh mount ls` and used by of `essh key ls` leave same rows out of tables; `on --all` and `off --all` take only what `ls` lists; `--json` keeps every row and marks this machine's with `self`. Naming hidden row or host still reaches it, as `essh <host>` does. `show_self` setting (Show self, off by default) lists them all again.
- Host order: Hosts list is `Host::jumped()` first, then `history::rank` (most recently connected first, then never-used alphabetically) or alias, per `host_order` setting. So `refresh_hosts` rereads history and calls `sort_hosts` every time (login started from any other essh moves its host too; `r` is how open toolbox sees it) and puts cursor back on host it was on (`select_host`), since reorder would otherwise leave it on whatever moved into its row and next Enter would log in elsewhere. Host with `ProxyJump` is route, not machine you sit on, so whole group sits under direct ones; sort is whole grouping, no column, no header, because taxonomy column repeated on every row costs alias and target columns more width than distinction is worth. `essh ls` stays alphabetical and ungrouped: script output must not depend on what you did yesterday.
- Adding setting: put it in `settings.rs` only (field, default, `set` arm, `rows()` entry); Settings tab, file and `d`-to-default key pick it up with no UI work. Cycled setting takes `choices`, changes in place on Enter; typed one opens one-field wizard. Every change saves immediately: no unsaved state, no save key. Setting running app acts on must also be re-applied in `apply_settings`, else takes effect only at next launch.
- Defaulting wizard field from setting: put value in field's `default` and read it back from there (`fields[i].default`), never from `Settings` again downstream, so live preview and command that runs cannot disagree. Mountpoint and sftp-server path both work this way.
- Action makes something (tunnel, mount): jump to its view with `goto_view`, select new row: `select_tunnel` right away; `new_mount` + `settle_new_mount` for mount, which exists in `/proc/mounts` only after suspended `sshfs` returns. Assigning `self.view` directly skips filter clearing, can land on tab hiding what you just made.
- Detail panel: renders for every view, only at `MIN_WIDTH_FOR_DETAIL` or wider, so narrow terminal keeps readable list. Reads only what is already loaded: never fresh command, never any I/O on mountpoint, since stale sshfs mount blocks `stat` and `df` forever and would hang draw loop.
- Showing path: `sshcfg::collapse_tilde` is display only (inverse of `expand_tilde`), so `Mount::describe` and panel agree with each other and with what user typed; `Mount::local` stays absolute because that is what `fusermount` is handed.
- Reachability: probes run on background threads, report over mpsc channel tagged with `reach_gen`; answer from older generation dropped rather than repainting list that moved on. Names resolved by `getent ahosts` child killed at probe timeout, never `getaddrinfo` in-process: glibc's `exit` waits on every stdio lock and `mdns4_minimal` holds one while avahi times out, so quitting would take five seconds with `.local` host in config. TCP connect answers "is anything listening", never "can I log in"; labels must not claim more. Host with `ProxyJump` never probed at own address (resolved on jump host, would answer about wrong machine): `sshcfg::first_hop` gives first hop of its chain instead, so dot is jump's answer and wears filled `◆` rather than `●` to say question asked one machine away, every word of panel's line naming jump. Route config cannot resolve (jump that is itself jumped, undefined alias) is `Reach::Indirect`, dim `·` distinct from hollow `○` of probe in flight, claims nothing. Probes started by `App::new`, by `r`, by settings change, and on return from anything that took terminal away, since dot learned before connect is claim about world we stopped watching.
- Image paste (`paste.rs`, `P` on Hosts): exists because Claude Code on Linux reads pasted image only by running `xclip -selection clipboard -t TARGETS -o` (piped into `grep image/…`) then `xclip -selection clipboard -t image/png -o` (its `image/bmp` and `wl-paste` fallbacks left to real tools). Host enabled by line in `~/.config/easyssh/paste` (`alias /abs/remote/dir`), written only after installer reports success, matched against destination exactly as typed, since alias logs in as the one user stand-in was installed for. Enabling behind red gate, because it lets that host (root included) read your clipboard image while connected; disabling behind one too, because it deletes stand-in there and only enabling gate plus remote install bring it back; on yes drops line first (alone stops forwarding), then removes stand-in. Stand-in (`paste/xclip.sh`, marked by `essh image-paste stand-in` line) goes to `~/.local/bin/xclip`, never over `xclip` lacking marker, passes every other call to next `xclip` in PATH; treats only grep's "no match" as "not ours" and refuses to pass call it was itself handed (`ESSH_XCLIP_PASSED`), because failing grep would make it `exec` itself forever. Install and remove scripts travel base64-encoded in ssh command line (`echo … | base64 -d | sh`), so stdin stays terminal for password and no fish or csh login shell parses them, with `RemoteCommand=none`, `RequestTTY=no`, `ClearAllForwardings=yes`; stdout captured (`PendingRun::paste`), read as `essh-paste:` lines. Remote socket directory absolute, learned from installer: ssh rejects relative `-R` socket path and would expand `~` on this side; path past `sun_path` (`MAX_SOCKET_PATH`) makes ssh abort whole login (`Bad remote forwarding specification`), not just forward. sshd decides whether stale socket replaced (own `StreamLocalBindUnlink`, default no; client's option covers only `-L`) and never deletes one when login ends, so every login binds fresh `<epoch>-<pid>-<n>.sock` (`n` counts logins of one process, since TUI keeps pid across them) and stand-in tries newest first, deleting ones refusing connection. Failed forward is warning ssh prints, never failed login, so never add `ExitOnForwardFailure`. For enabled host `essh <host>` does not `exec`: spawns ssh, serves clipboard from thread on 0600 socket under `$XDG_RUNTIME_DIR/easyssh`, catches SIGINT and SIGQUIT with `signal-hook` and does nothing with them, never `SIG_IGN` (ssh would inherit it and stop honouring Ctrl-C), exits with ssh's code or `128 + signal`. TUI's Enter shares `paste::serve_for`, drops `Forward` the moment login returns. Every other host keeps plain `exec`.
- Yanking: clipboard is whichever of `wl-copy`, `xclip`, `xsel`, `pbcopy` is on PATH; status names it (`copied … (wl-copy)`); with none installed, say which would work rather than failing silently. Nothing bundled, nothing installed.
- TUI navigation: `j/k` and arrows move; `h/l`, arrows and Tab switch view; leftover Ctrl-chords navigate, never act. In wizard `h/j/k/l` are typed text, so fields move with `Ctrl-j/k`, `Ctrl-arrows`, `↑↓` or Tab. Typed text edited through `tui::line_edit` only, in every form field and `/` filter; cursor is `back` (characters after it), so code assigning value without knowing about it leaves cursor at end. `Kind::Choice` field is exception: holds no text, so `h/l` and arrows (with or without Ctrl) move its answer; leave it with Tab, Enter or vertical keys. Two-option choice stops at edge, no wrap; longer one cycles.
- Host form's ForwardAgent: no/yes toggle opening on what ssh would really use (`sshcfg::forward_agent_for`, wildcard blocks included), writes line only when answer differs from that, so untouched toggle adds nothing and user's own `ForwardAgent no` never stripped by edit. Change earlier block would override refused before anything written (`check_forward_agent`), because save ssh ignores reports change that never happens; here that is agent reaching machine user shut it out of. Add form never writes `no`, since new host has no own line to cancel. Socket path already in config becomes third option.
- Add/edit-host wizard stars Alias alone, because `submit_prompt` refuses only that: `Host raspi` with no HostName valid whenever alias itself resolves, so starring HostName would mean enforcing it and taking that host away from TUI; blank User no omission either, it is ssh using your login name, the point of leaving it out. Public key in IdentityFile refused (`keys::is_public_key`) with private path to use instead; nonexistent path saved with yellow warning, except one ssh expands itself (`%d`, `${HOME}`, quotes), uncheckable from here.
- Wizard fields are `Kind::Text` or `Kind::Choice` (cycled in place); `shown_when` hides one until another field's choice selects it. Hidden fields keep slot so field indices stay stable; `visible`, `step` and `on_last_field` keep navigation and Enter off them.
- Every overlay goes through house box in `tui::widgets` (`box_block`, `box_buttons`, `box_hint`, `box_width`, `box_inner_width`, `box_height`, `box_area`), never hand-rolled `Block`. Measure body with `wrapped_line_count(text, box_inner_width(width))`, hand *wrapped* count to `box_height`, which adds chrome.
- Mounting as root: sshfs's channel has no tty, so `sudo` cannot prompt; wizard offers exactly one sudo mode, `-o sftp_server=sudo <path>`, needing NOPASSWD sudoers line scoped to sftp server. Never add "send the password" mode: every way of feeding one from here (piping to `sudo -S`, priming ppid ticket) puts password in command line, where `ps` shows it to every user on both machines. Hiding it would take owning SSH client, not a flag.
- Status messages transient: `set_status`/`set_failed`, cleared after `STATUS_TTL`. Event loop polls while message showing or `probing()` true, blocks otherwise, so idle TUI costs nothing.
- Stamping connect: login counts from moment it starts, in TUI as in `essh <host>` (which `exec`s, has no after), because one still open, one whose terminal was closed and one that dropped never reach an after. TUI login exiting 255 with nothing in ssh's stderr showing session ever started (`connect::ending` answers `NoSession`) taken back off with `history::unrecord`, so failed login leaves ordering as it was.
- Starting login (TUI Enter and `essh <host>`): `commands::connect::keepalive_args` puts `-o ServerAliveInterval=<keepalive>` before destination, because ssh's default never checks server still answers, so connection whose network went away freezes until TCP gives up (about 15 minutes while typing, two hours idle) and one whose address changed never resumes. Left out when `keepalive` setting is off, when user's own ssh flags name option, and when config sets it for host (`sshcfg::sets_server_alive` over `~/.ssh/config`, its Includes and `/etc/ssh/ssh_config`: `Host` line counts only when no negated pattern on it matches, line before any `Host` counts for every host, one under `Match` counts as applying since condition not evaluated; `0` turning it off included), since command-line `-o` beats every config file. With default 15 and ssh's `ServerAliveCountMax 3`, dead login ends after three unanswered checks, at fourth interval: about a minute.
- TUI login ends: stderr copied to screen as it arrives, last bytes kept (`Capture::StderrTail`, through `Tee`, which waits a moment for ssh's last words, never for end of pipe, since ProxyJump's `ssh -W` can outlive login and hold it open). On 255, `connect::ending` reads them: ssh's session-loop lines (`Timeout, server … not responding.`, `client_loop: …`, `Read from remote host …`, `Connection to … closed by remote host.`) mean session was up and connection went, so yellow `connection lost` alert goes up at once, no probe; `Connection to … closed.` is `~.`, stays status line; anything else, or any `kex_exchange_identification` line, is login failed before session, which gets probe below, list drawn under `checking why` status first, because probe can take its whole timeout.
- Failures user must act on never sit in status that flashes past. One classifiable into next step becomes **offer** (`Confirm::offer`, see below): connect exiting 255 before session started is probed again with `connect::diagnose` (BatchMode, plus `-o RemoteCommand=none`, because ssh refuses command line on host forcing one before it even connects), which offers `ssh-keygen -R` for changed key and `IdentitiesOnly yes` for agent offering too many keys, and explains refused, unresolved, unreachable and keys-only failures in alert with ssh's own lines. One with nothing to propose becomes **alert** (`tui::alert`, yellow, dismiss only), where program that could not be started at all ends up. Probe runs only after failed connect, so success path costs nothing. Busy unmount not offer: asks behind gate (`Confirm::new`) whether to force `fusermount -u -z`.
- Wizards show live `command_preview` rebuilt from current fields, so user sees exact `ssh-keygen`/`sshfs`/`ssh -L` command while typing. Keep preview's value resolution identical to `submit_prompt`, or preview lies.
- Installing key (`Y` on Keys): ssh-copy-id must log in first, so picked host probed with `connect::diagnose` on background thread (`start_copy_check`, status line saying so until `drain_copy_check` picks answer up, dropping it if another box opened meanwhile); key that already works or password method goes to plain ssh-copy-id; only `Diagnosis::KeysOnly` gets offer to go through another host. `ProxyJump` only carries connection, so last hop always logs in with this machine's keys and jump host that can log in there does not help. Offer picks host already able to log in (last hop of target's `ProxyJump` first, stripped of `user@` and `:port`) and runs `keys::install_via_argv`: `ssh -t <via>` running base64'd `sh` script that runs `ssh -l <user> <target>` from there, which appends `.pub` line with second base64'd script. `-t` and command-line scripts keep both hops able to ask for password, which is also why output cannot be captured and result travels in exit code: `keys::ADDED`, or `keys::ALREADY_AUTHORIZED` when uncommented line already lists key (so refusal is about User or permissions instead). Success never 0, because failing `base64 -d` feeds `sh` nothing and `sh` then exits 0. Via reaches target by alias when its own config defines it (`ssh -G` there answers with HostName other than lowercased alias), else by our resolved HostName and port, always as our resolved User (`sshcfg::resolve`, `ssh -G` here), since that is authorized_keys this machine logs in to.
- `Confirm` is gate (`Confirm::new`) or offer (`Confirm::offer`), told apart by `danger` flag. Both answer `y`/`n` directly, move with `h/l`, arrows, Tab and Shift-Tab, cancel on Esc or Ctrl-C, ignore any other key so stray press cannot answer.
- Help overlay is `HELP` table in `render.rs`, one `(keys, what)` row per key; `render_help` clamps `help_scroll`, since only it knows height.
- Interactive children (connect, keygen, copy-id, adding key through another host, mount, image-paste install and removal) run suspended: leave alt-screen, run so they can prompt for passwords, restore. Tunnels detached, skip this. Run whose output is read afterwards (`PendingRun::paste`) captures stdout and stderr and prints its label first, since ssh still prompts on tty; every other run copies stderr through (`Capture::StderrTail`, above): non-login run exiting non-zero has those lines (`connect::said`) shown with its command through `report_failure`, so sshfs's or ssh-keygen's reason not lost under redrawn list. While child runs, `commands::connect::swallow_interrupts` catches SIGINT and SIGQUIT.
- Suspending TUI: call `show_cursor()` after leaving alt-screen, because draw loop hides cursor and leaving alt-screen does not restore it; else child runs with invisible cursor.

## Overview
Layout:
- `src/main.rs`: clap `Cmd` enum and dispatch match, nothing else.
- `src/commands/<verb>.rs`: one file per CLI command (`connect`, `ls`, `cp`, `host`, `tunnel`, `mount`, `key`, `check`, `completions`, `selfcmd`), each exposing `run`; `mod.rs` holds what they share (`-n`, `--json`, `step`, `fail`, `run_tool`).
- Adding to CLI: noun per TUI tab, built on same domain calls tab uses (`tunnels`, `mounts`, `sshcfg`, `keys`, plus `tui::mount_spec` and `tui::connect::probe` from TUI), so row made one way is row the other way. Change prints one stdout line per step, `-n` prints exactly those lines and stops; listing takes `--json` with fixed field names; anything ssh's tools would ask runs with their stdout sent to our stderr (`run_tool`), so stdout stays command's own. Every verb is word `essh <host>` can no longer reach, which is what `essh -- <host>` (handled in `main` before clap) is for.
- `src/tui/`: toolbox: `mod.rs` owns `App`, event loop and terminal handling; `input.rs` dispatches keys per view; `wizard.rs` is what submitted prompt does; `prompt.rs` field machinery; `picker.rs`, `confirm.rs` and `alert.rs` their overlays; `mount_spec.rs` sshfs command mount wizard builds; `render.rs` frame; `detail.rs` panel beside list; `filter.rs` what `/` keeps; `widgets.rs` domain-blind furniture; `line_edit.rs` one line of typed text with cursor and emacs keys; `connect.rs` reading ssh's failure output; `paste_run.rs` what `P` does and how its remote script's report is read; `tests.rs` `TestBackend` tests.
- Top-level domain modules: `sshcfg` (parsing and editing `~/.ssh/config`), `keys`, `tunnels` (forwards you keep and ones running), `mounts`, `history` (when you last connected where), `reach` (background ssh-port probes), `machine` (which hosts are machine essh runs on), `clip` (system clipboard), `paste` (image paste into remote Claude Code: enabled-hosts file, clipboard server login carries, remote scripts in `src/paste/`), `completion` (Tab completion through clap_complete's `COMPLETE=<shell> essh`, whose script `essh completions <shell>` prints and `--add` writes loader line for once, with bash adapter gluing `host:path` back together after bash splits it at colon), `settings` (`~/.config/easyssh/settings`, including `keepalive` login gets).

`easyssh` is Rust CLI and TUI making ssh simple: one binary `essh` in place of `ssh`, `ssh-keygen`, `ssh-copy-id`, `scp` and `sshfs`, plus hand-editing `~/.ssh/config`. Smart frontend, not reimplementation: every action shells out to real tools, so ssh-agent, keys and existing config keep working. Bare `essh` opens ratatui toolbox with Hosts, Keys, Tunnels and Mounts tabs and their wizards; CLI does connect, `ls`, `cp`, tabs' own actions through `host`, `tunnel`, `mount`, `key` and `check`, plus `completions` and `self` (`self update`, `self check`).
